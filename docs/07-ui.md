# UI (Next.js, private)

The UI queries Postgres directly (`06-pipeline.md` §5-6) and calls Jev live only from the ask box
and search. The pipeline comes first; the UI is built after the first 10k slice.

## Nebula (main view)
A 3D nebula in which **every node and every displayable question is drawn**, all the time. Detail
reveals itself as the camera gets closer. Precedents: OneZoom (everything drawn, detail on zoom), CAIDA
Walrus (300-500k-node trees drawn as glowing 3D spheres), datamapplot and Nomic Atlas (labels resolve on zoom).

**Layout (deterministic, so you can learn where things are):**
- The root sits at the center. World / Self / Machine are three lobes, 120° apart, each only as far
  out as its own size needs.
- Every node's children sit on a spherical cap facing away from the node's parent. This is a 3D balloon tree.
  - Each subtree is summarized by its real bounding sphere, which sits ahead of the node, and siblings
    may share part of that mostly empty space. A deep, narrow branch then grows about linearly with depth
    instead of doubling its empty space at every level.
  - The gap between a node and its children shrinks with depth, small subtrees sit closer in than big
    ones, and each child's distance varies a little, so branches don't look like spokes. A final pass
    nudges apart any balls that touch.
- A node's own questions form a ball of stars around it, with radius ∝ ∛(question count), so big topics
  look big instead of crowded. Stars gather in a dense core with a soft halo, and each ball is slightly
  stretched and flattened along a hashed axis, so clusters don't all read as identical spheres.
- Inside a ball, a star's direction comes from a 3D PCA of that node's question embeddings, and its
  distance from the center is rank-normalized. Neighboring stars ask similar things.
  `scripts/star_layout.py` (read-only on Postgres) precomputes this into `data/stars/`, which is served by
  `/api/stars`. Re-run it after the pipeline or any restructure. The tree part is computed in the browser.

**Layouts (the search window's Layout tab, one row of six; keys 1-6):** Web is the default; the others exist to compare
arrangements of the same tree. All of them place node centers and ball sizes (`web/src/lib/layouts/`),
and stars, edges, labels and the camera read the same result, so switching is live. The choice is kept per
browser once someone picks one (the default is never stored, so a new default still reaches everyone), and
`?layout=<id>` opens a specific one.
- **Balloon:** the cap layout above.
- **Galaxy:** each hemisphere is a tilted spiral disk. Each L1 topic is a logarithmic arm, and each of its
  subtopics is a knot along the arm with its subtree packed around it like a sunflower head.
- **Bubbles:** nested sphere packing. Each topic's sphere holds its own ball and its children's spheres.
- **Onion:** depth is distance from the center. Each level is a shell, and each topic owns a patch of sky
  sized by its subtree, cut in balanced halves so patches stay near square.
- **Web:** force-directed. Tree edges are springs, all nodes repel (Barnes-Hut), starting from the balloon
  tree for a fixed number of steps.
- **Meaning:** each node sits at its mean question embedding, projected to 3D (UMAP-style over a
  k-nearest-neighbor graph, PCA start, fixed seed). It's computed on the server from local embeddings by
  `/api/layout` and cached until the star snapshot changes. Topics that ask similar things sit together
  across branches. Switching to it is instant: once the opening has played, the page fetches the coordinates
  and runs the layout's overlap pass (~0.5 s) in a worker (`semantic.worker.ts`) in the background, and keeps
  the result in the browser keyed by the tree's shape and the coordinates. Any layout still computing (Web or
  Meaning) never freezes the page or flashes a stand-in: the current layout stays until the new one is ready.

**Drawing:**
- **Questions:** every displayable question as a point sprite in one draw call. The particles themselves
  are the cloud, like the typesafe.ai header. A star smaller than one dither cell is drawn by chance in
  proportion to its size (fixed per star, so nothing flickers), so a distant cluster keeps its brightness
  as stipple while the GPU skips most of its pixels.
  - By default each particle takes its hemisphere's color, shaded per L1 branch. Indicator colors come
    from the question's own `question_meta`.
  - Particles that need attention (fragile, large human gap) are bigger and magenta, so they stand out
    from a distance.
- **Nodes:** brighter stars sized by depth.
- **Indicator weather:** only while the sky is colored by an indicator, pale puffs around each node take
  its indicator color, so where Jev is jagged shows from far away. Colored by hemisphere there is no gas:
  the particles are the cloud.
- **Filaments:** tree edges drawn as curved light that flows outward, plus the search / Jev-path pulses.
  Question→node edges are never drawn; membership is shown by position.

**Opening:** fireworks, breadth first (`fireworks()` in `lib/anim.ts`). When the questions arrive, the root
lands first; each node then flies out from its parent along its branch (small, like a rocket, 0.5 s, the branch
drawing behind it) and bursts on landing: a pop, its question dots spraying out of it with a slight overshoot and
a pink flash, while its own children launch, slightly staggered. The show ripples outward level by level (about
5 s at today's depth) while the camera starts close on the root and pulls back to the home view. Each hemisphere
is named just after it lands; other labels, question labels and hovering wait until it has settled. The home
view looks across the nebula at about 10°, so the horizon sits in the upper part of the frame with sky behind
the data.

**Theme:** only the map has a dark mode. Its switch sits in the search window's title bar as a slider: one control,
any click flips it and a white thumb slides (220 ms) under the current icon (a round sun, a crescent), inset from
the window's edge, fixed width. The portrait and
atlas pages are always dark, with no toggle: the first-paint theme script sets dark on every page but `/` (which
gets the saved or system theme), and arriving from a light map, those pages switch to dark and restore the map's
theme on the way back.

**Labels in the sky:** one rule per kind, the same in both themes. Every topic, at any depth, is a black bar
with white pixel type (TypeSafe's title bars); size alone shows level. Every question, including the landed one's
callout, is the inverse: a white box with black type and a thin black rule. Hemisphere names are big sans type.
Hover and selection turn a label magenta (Jev's color); the live search's category gets a pink offset shadow.

**Icon:** a play on TypeSafe's logo (interlocking isometric blocks in heavy black line on hot magenta): a question
mark built from the same blocks, one block deep, projected isometrically and seen as their blocks are: the letterform on the left
vertical plane, viewed from below, so the hook's loop becomes a hexagonal frame with a small cube in its inside
corner, like their left piece (the dot sits 1.5 blocks below the stem so the two don't touch), with lines on creases and silhouettes and
none on the seams between blocks sharing a face. `icon.svg` is the line art as vectors on a transparent background, like TypeSafe's own tab icon: white on
dark tab bars and ink on light ones (a `prefers-color-scheme` rule inside the SVG), hidden lines removed with
masks since there's no background to paint over them, stroke as heavy as theirs at 16 CSS px; `apple-icon.png` is the line art at
180 px; `favicon.ico` is the small raster fallback, drawn solid (white top, ink side, plum front) because thin
diagonals smear at 16 px (`web/scripts/make_icon.py`).

**Checking the look:** `web/scripts/ui_shots.mjs` renders six fixed camera poses (home, high, level, looking
up from the side, close, far) in both themes through a dev-only camera handle, and `ui_sheet.py` tiles them;
`ui_intro.mjs` records the opening as a frame strip.

**Alive, but data-driven:**
- Stars twinkle with an amplitude set by their instability.
- Balls rotate slowly around their node, with deeper levels turning faster. The layout itself never
  moves.
- Idle replay: random stars flare as if their question were being asked again.

**Text on approach:**
- Node labels are prioritized by depth, size, path, and hover. They are placed greedily in screen
  space with collision checks, about 60 at most.
- Close to a topic, its question texts load and the stars nearest the middle of the screen get labels,
  24 at most. Stars that share a text (a template run over many inputs) are labeled by what differs:
  the input or the options.
- Hovering a star shows its text. Clicking the star, or its text label, flies in and opens its question card.
  While the camera flies, question labels fade out rather than reshuffle, and the landed dot gets crop-mark
  brackets (as on typesafe.ai's sections) with its text above. Text floating over the sky can't be selected.
- Zoom goes toward the cursor, and scrolling over a label zooms too (the label hands the scroll to the canvas).

**Getting somewhere:**
- One box does both search and ask. As you type, results appear; the last row is "Ask Jev: '...'", which
  opens the ask flow pre-filled.
- **I'm feeling lucky** flies to a uniformly random displayable question.
- A search result or a lucky pick starts a **journey** straight to it: the result was already chosen (local
  embeddings, then one Jev rerank), so there is no further Jev call on the way. The camera follows a lit
  ink trail down the question's stored path at a readable pace (0.45 s per level; a chip names each node),
  closes in on the question's own dot (crop-mark brackets and a callout of its text), keeps it centered
  while its ball turns, and only then opens the card. Clicking a dot lands directly.
- **"Where Jev would file it"** is on demand, on every question card: one `/api/walk` beam walk for the
  question's text. Jev's path runs as a magenta trail with its confidence at each node ("JEV ▸ Food
  Preferences · 93%") beside the ink trail of where the question is stored, and the card says whether they
  agree. Most questions were placed from their source's labels, not by Jev (`placements.method`), so the
  magenta trail is Jev's own decision and the ink one is only where the question is stored.
- Node labels are clickable and do the same as clicking the node.
- **The selected topic** gets four static crop-mark corners (typesafe.ai's section corners), the same mark a landed
  question gets, at a fixed on-screen size. (It used to be a rotating open ring, which read as a loading spinner.)
- **The lit trail always matches what's open.** However a question is opened (its dot or label, a topic's list, a
  thread link, Back, a deep link), its root-to-question trail lights quickly in ink (white in dark mode), replacing
  any earlier trail, its dot is marked, and the camera moves straight to the dot from wherever it is: no ride back
  to the root, which only search's journey does. Opening a topic lights that topic's trail. (`revealQuestion` and
  `lightPath` in `lib/actions.ts`.)
- The view controls live in the search window's tools row, like the tabs under a search engine's box:
  **Layout** and **Color** name their current setting, **Filters** is a funnel icon (filled, with a count, when
  any are on), and each opens a panel docked right under the box (one at a time; typing in the box closes it).
  Layout and Color are one-line segmented rows; the chosen segment inverts (ink fill, paper text) with its frame
  kept. The tabs truncate before "Feeling lucky", ⌂ or the funnel ever do, and on phones the segments shrink
  their type rather than wrap. Color offers Hemisphere, Stability, Human gap, Frame gap and Calibration;
  placement confidence isn't a color (72% of questions were filed by their dataset's own category, stored as
  100%, so the map would mostly show that default), but it stays on cards and topic stats. While the sky is colored by an indicator, a
  small legend sits bottom-left. The usage hint fades after a few seconds.
- The camera is a damped orbit with a home view.

- **Universe switcher (later):** recolor the same nebula by drift in a chosen universe (terse,
  old-english, negated...). Universes are overlays, so the tree itself never changes.
- **Filter by tag:** kind/shape, primitive, origin. Nodes and stars that don't match dim.

## Look: TypeSafe's brand (typesafe.ai)
askjev is outreach to TypeSafe, so it borrows their visual language: light, printed, dithered, and "old OS".
Colors are typesafe.ai's own design tokens; `web/src/lib/theme.ts` holds the 3D side, `globals.css` the page.
- **Sky:** twilight over a still sea, a stylized take on a real dusk (the colors follow the actual order of
  twilight). The sun has just set in one fixed direction (behind the nebula from the home view), so the
  scene has a warm side and a cool side and reads as a place as you orbit:
  - the dome runs warm and light at the horizon to cool and deeper overhead; the twilight glow sits low on the
    sun's side, and opposite it the Belt of Venus (a pink band) rests on Earth's shadow (a blue-grey one);
  - a band of cumulus sits low in the sky, sampled on a cylinder around the viewer (3D noise at cos/sin of the
    azimuth, and elevation) so the puffs stay round at any heading and wrap all the way round with no seam. The sun is below them, so they're lit from underneath: toward the sunset they're silhouettes
    with glowing pink undersides (like the lakeside reference photo); away from it, bright tops over shaded
    bases. Faint cirrus streaks run higher up;
  - overhead, a high deck of mackerel clouds (rows of small cells with holes of open sky), drawn on a plane far
    above so the cells shrink toward the horizon. It starts about a third of the way up, so the home view keeps
    a clean horizon. Light mode: pale pink toward the sunset, lilac away from it. Dark mode: dim violet
    silhouettes barely off the night sky, as real high cloud looks after dusk, with stars in the gaps and only a
    muted plum edge toward the sunset. In dark mode the afterglow is dimmer and hugs the horizon (`glowFall`
    15 vs 6 by day) so the band behind the nebula stays low-contrast, the dark palette carries two in-between
    inks (#35295C, #5E3F78) so the gradient steps smoothly instead of banding, and cloud rims are softer. Its strength is set per theme (`deckAmt`), because the backdrop has to
    stay lower in contrast than the data in front of it: an early version with hot-pink edges fought Self's
    pink and the dots. Looking up is no longer an empty gradient;
  - below the horizon a calm sea. Looking down you see the water's own deeper color (`waterDeep`: periwinkle by
    day, near-black at night), and only toward the horizon does it turn into a mirror of the sky (soft and a shade
    darker: three offset samples, the deck at half strength). Its own texture: short horizontal wavelets fixed to the water, finer with distance,
    their crests catching the low sky, crossed by a second diagonal swell so the pattern keeps shifting, plus
    wind patches and a soft, wide pink sheen toward where the sun went down (no moving streaks or glints: in the
    dither they read as dancing pink dashes, not water). Everything drifts slowly: the wavelets, swell and ripples, and the
    cumulus, cirrus and high deck drift and slowly change shape (all driven by time in the sky shader). The
    sea is always a step darker than the sky it mirrors (`seaDim`: 0.95 by day, 0.72 at night, where the sunset
    glow would otherwise run straight into its own reflection), up to a clean horizon with a thin light line;
  - the water sits a third of the nebula's height under its lowest ball (it follows the layout, easing on a
    switch), and the nebula reflects in it (`Reflection.tsx`), after the photos of harbor lights on rippled
    water: every 18th question dot becomes a tall thin column of short wavelet dashes that jitter and flicker,
    sway with the ripples and break up along drifting swell lines. It's weighted by Fresnel (water reflects ~2%
    looking straight down, mirror-like only at grazing angles), so from above it all but vanishes and it only
    glimmers when you look across the water. Subtle at most, by design.
  Pink is an accent (the horizon band, the belt, cloud undersides, the glitter): roughly a fifth of the frame.
  The dome is centered on the camera at draw time, so no flight can outrun it. The questions are colored
  particles (World blue, Self salmon, Machine orange; orange is the one non-brand color, kept so the three
  hemispheres separate), and stars behind the point you're looking at fade a little (aerial perspective).
- **Light theme:** an evening in typesafe.ai's hero colors: their pale sky blue overhead and in the water, a
  pink horizon, lilac-grey clouds with hot-pink undersides.
- **Dark theme:** the same place after dusk, in the colors of their dark docs site (docs.typesafe.ai:
  aubergine black, mauve greys, one hot-pink accent): violet-black overhead with stars, a plum-to-magenta
  afterglow at the horizon, near-black cloud silhouettes rimmed in hot pink, and a dark mirror sea with pink
  glints. Lighter shades of the hemisphere colors, white filaments and paths.
  Title bars, pressed chips and primary buttons are always light text on a dark bar, in both themes; window
  bodies are grey in light and near-black in dark. It follows the system setting until toggled ("☾ Dark" /
  "☀ Light" in the search window's title bar), and the choice is kept per browser.
- **Halftone:** the whole 3D view is printed onto the theme's 16 inks at 2 CSS px cells, like a print run. Each cell finds the two inks it sits between and picks one by that pair's screen, and each ink
  has its own screen, as in their dithered photos (and only neighboring inks ever mix, so the sky's bands
  stay clean): fine organic grain for sky and cloud shading, round 45°
  dots for the pinks, horizontal lines for World blue, diagonal lines for Machine orange, a plus grid for
  Self salmon. Colors already on the palette stay solid. The scene renders at exactly one pixel per cell (half the CSS size) and the canvas is
  scaled up with crisp pixels, so the GPU shades a quarter of the CSS pixels (about 3.5× the frame rate
  of rendering at full resolution). Text labels sit above the filter in HTML, so they stay sharp.
- **Palette:** ink `#1E1E1E`, off-white `#FEFEFE`, window grey `#DEDEDE`, salmon `#F386A1`, magenta
  `#D45BB6`, hot-pink cloud `#FF78F2`, blue `#4B5BD6`, orange `#E8663D`, teal `#09AEA1`,
  sage `#ABBAB9`, sky `#DBF0FF`. Indicators run from blue (steady) to magenta (worth a look).
  Magenta `#D45BB6`, typesafe.ai's main color, is Jev's and the selection's: its pick, its walk and trail, the
  selected label and marker, and the nav hover. It sits close to Self's pink, so on a selected Self topic the
  crop-mark corners carry most of the signal, and it shares a hue with the indicators' "worth a look" end.
- **Type:** TypeSafe uses Die Grotesk C, LisaTerminal Paper, and JetBrains Mono. The first two are licensed,
  so askjev uses free stand-ins: Inter Tight (headings/body), VT323 (window chrome, chips, labels), and
  JetBrains Mono light (tiny captions).
- **Components:** every panel is a flat OS window. Each has a black title bar in pixel type ("Color.Tool 1.1"),
  a grey body, a hard double border, no rounding, and no blur. Tags are black or colored chips in pixel type.
  Meters use ■ markers, and scrollbars are square ink thumbs on window grey. The page also has crop-mark
  corners and a vertical base64 caption.
- **Search window (top left):** one window. Its title bar holds the name, the question count and the theme
  toggle. The box follows the usual search pattern (and typesafe.ai's docs search): a magnifier on the left,
  "Ask Jev anything", the result time while you type, and a mic on the right (`/` or ⌘K focuses the box
  from anywhere). The mic uses the browser's own speech recognition (Web Speech API: free, no key; Chrome,
  Edge and Safari run it on their speech service); words stream into the box as they're heard, and it
  stops at the first pause. Where the browser has none (Firefox), there's no mic. Below the box, the tools
  row: Layout, Color, the Filters funnel and "I'm feeling lucky" at its right end, never clipped, like the chips under a search engine's
  box. No tagline.

## Side panel
- One tall window on the right, for a topic, a question, or the ask box, built like a small browser: a title
  bar ("Topic.View 1.1") with close (also Escape, or a click on empty sky), then **‹ Back** and **Forward ›**
  (Backspace / Alt+← and Alt+→) beside the path shown as an address bar.
- **No layout shift on state changes:** a control never moves because something beside it changed. Headings stay
  constant when a toggle switches (the toggle names the state), buttons keep their width across states ("Ask Jev" /
  "Walking…" / "Walk again"), tool-tab values reserve their longest option, and status text sits in fixed slots.
- The panel remembers every topic and question it showed until it closes, so Back and Forward retrace the way
  you came, as in a browser. The path is always one line, so the header never changes height: when it
  doesn't fit, its leading steps fold into a "…" step (click it to go up to the last folded one), as file
  browsers do, so every step shown is a whole word; no fades or cut letters.
- Stale-while-revalidate: every topic and question fetched is cached, and hovering a link fetches it ahead.
  Hovering a question dot fetches its card too, and clicking a dot opens the card at once while the camera flies in
  (it used to wait for the 1 s flight). Topic counts come from per-topic counts cached in the server
  (`lib/server/counts.ts`, one grouped count, refreshed every 5 min), so opening a hemisphere or the root is
  ~20-60 ms instead of 0.5-1.5 s; only a filtered list is counted live. Dot hover previews are trimmed (text 220,
  label 140 chars, label sent only when it differs), which took the largest topic from 8 MB to 2.7 MB.
  The page on screen stays until the next one's data is in (a thin pink line runs under the address while
  it loads), so the panel never flashes a loading state; Back and Forward are instant.
- A topic shows its place in the tree: its parents from the root down to it, then its subtopics with their
  question counts (the first 12, then all on request), each one click away; then its indicators, kinds, and
  questions: its own first (most asked first), then the rest of its branch. "Show more" pages by cursor, not
  offset (`/api/node/<id>?page=1&after=…`), so each page is a few ms even on the whole tree (it was ~3 s on All);
  the button says how many are showing, shows it's loading, and says so if a page fails.

### Question cards
- Question text, primitive, frame toggle (self / human / human@country).
- Distribution bars (Choice/Noul) or bands (Score; never the interpolated scalar).
- Stability strip (agreement across shuffles; a "fragile" badge) and, where sampled, the answer in each
  universe side by side.
- Jev's self-assessment (objective / ambiguous / disagreement) next to the measured values.
- `ask_count` and the follow-up thread (`question_links`).
- Human overlay and/or truth marker where available.
- A link to the raw request/response and the served version.
- Framing text on Self cards: "Jev's default", never "Jev believes".
- A small pixel **i** beside each term that needs the pipeline to make sense (the answer frames and reported
  confidence, stability, Jev's read of the question, frame gap, human gap, matches truth, placed by, where Jev
  would file it). Hover, focus or tap opens a mini OS window (title bar, plain-words body, pink offset shadow)
  that stays inside the panel, opening upward near the bottom. The text says what the number is and how it's
  made, in the site's own terms, and never calls a value a score or ranking.

## Search (instant, then refined)
- As you type: the query is embedded on the server (bge-small, half precision: 67 MB, and the same top-1 and
  top-20 as full precision on 30 test queries) and the 20 nearest questions come back from pgvector. Search
  takes about 140 ms end to end locally. A trigram leg used to run beside it; on the 30 test queries it never
  changed the #1 result (top-5 overlap 95%) and cost ~590 ms of database time, so it was removed.
- **Every keystroke searches, but half-typed words don't.** An embedding has no prefix matching, so "is a hot d"
  scattered results across three unrelated branches before "dog" landed. The searched text leaves out a
  trailing fragment under 3 characters until it grows or a space commits it (`settled()` in `Search.tsx`).
  Keystrokes within 50 ms coalesce, stale requests are cancelled, and the last 200 searches are cached in the
  page, so backspacing is instant.
- **The map is live heat** (`lib/heat.ts`), in ink. Each of the top 20 lights its question dot and every branch
  on its path to the root, weighted by closeness and rank, so branches shared by many results glow brightest.
  The deepest topic holding over half the weight is the category, labeled with a pink offset shadow (an
  underline on a hemisphere). Everything outside the heat fades back while a query is live. The heat changes
  only when the results really change (a new #1, or fewer than 7 of the top 10 shared), and every change eases
  in over ~300 ms, so it drifts rather than blinks. It all runs in shaders and per-frame refs with no Jev call:
  typing a 23-character query at ~70 wpm holds 60 fps with no frame over 34 ms (`web/scripts/ui_typing.mjs`).
- **Results list** (the top 20 after grouping; 40 candidates are fetched so grouping still fills it):
  - **Rewordings fold into one row.** Candidates at cosine ≥ 0.95 to a row's lead (measured: rewordings sit
    0.95-0.99, genuinely different questions beside them ≤ 0.93) join it as "+4 rewordings"; same text with other
    answer options folds as "+28 with other options". A row whose rewordings Jev answers differently says so
    ("answers differ"): search shows jaggedness directly.
  - **Each row shows Jev's stored answer** (its top answer and probability) in a fixed-width column, and the last
    two levels of its path (the full path on hover).
  - **The header row is fixed height:** the closest topics as chips on the left, a fixed status slot on the right
    ("Exact match" when the best match is near-exact and Jev is skipped; "Jev is ranking" / "Ranked by Jev").
  - **"No close match":** the reorder request also asks Jev a Noul, "does any candidate ask what the query asks?"
    (a Choice always crowns a winner). Measured: real questions 0.77-0.99, nonsense and topics the corpus lacks
    0.03-0.28. Below 0.35 the header says "No close match" (in place of the topic chips, so nothing below moves)
    and the rows fade; 0.35-0.7 says "Related, not exact". Jev's #1 is tagged "Jev's pick"; no per-row percentages.
  - **"Ask Jev" is pinned** to the bottom of the list. No latency or match count is shown.
- **The animation is decoupled from latency.** The chosen result's stored path runs at a readable pace.
- **Jev refines in the background.** Once typing pauses (700 ms after the last keystroke, whether or not it
  changed the searched text), one request reorders the top 20, and results reorder smoothly. Jev's pick is
  drawn in magenta down its path on top of the ink heat, with its dot lit. It's skipped when the best match is near-exact (similarity ≥ 0.95; Jev never changed the #1
  there). `web/scripts/rerank_eval.mjs` measures it: on 30 queries Jev changes the #1 about half the time
  (clear wins like "how tall is mount everest" → "What is the highest mountain in the world?", many
  near-duplicate swaps, one miss), median 243 ms.

## Clearing
Two layers with different owners, cleared separately:
- **The query** belongs to the search box: the text, the ink heat and Jev's magenta pick. Clicking around the map
  keeps it as a lens (while a panel is open the rest of the map fades less, so the panel's subject reads). It
  clears with the **✕** in the field or a second **Esc** while typing (the first closes the result list).
- **The selection** belongs to the side panel: the topic or question, the flight trail and the landed dot.
  Closing the panel (its ✕, or a click on empty sky) clears all of it. Jev's pick lives only while its result
  list does: any navigation clears it, so there's only ever one magenta thing on the map.
- **Reset view** clears both and flies home: click **Map** in the site nav (the page you're on), or **Esc** on the map, which peels one
  layer per press (open tool, then the selection, then everything).
- The search box never fills with what you clicked; the panel's title and breadcrumb say where you are.

## Deployment (Vercel + Postgres)
The site deploys from `web/` to Vercel and reads a **trimmed copy** of the database (`scripts/sync_prod.py`),
not the pipeline's: the pipeline, `data/` (raw sources and call logs, ~35 GB) and the full database stay local.
- **Copy (~5–6 GB of the pipeline's 10 GB):** only the tables the site reads, only displayable
  questions and their rows; the Jev call log
  without raw responses (cards only show the served version and timing); no foreign keys.
- **Sync without downtime:** the copy loads into a `stage` schema while the site keeps serving the current one,
  and one transaction swaps the tables in, so a failed sync leaves the live copy untouched. Before each big copy
  and index build the sync waits for the target's write-ahead log to drain under 1 GB: a load writes the whole
  database again as log, and an unthrottled first load filled a 10 GB disk and turned the branch read-only.
  Jev calls the site cached since the last sync carry over. Every table is read from one source snapshot, so
  pipeline writes during the hours-long copy (a question hidden mid-sync) can't split the copy. The upload is the slow part (~0.5 MB/s from a home
  connection, ~2 h for 1.05M questions): questions and vectors copy in binary (the vectors are a sixth of
  their text size), the rest as text.
- **Routine refreshes: `sync_prod.py --delta`.** Only the questions added or hidden since the last sync: new rows
  load into a `delta` schema, then one transaction removes, adds and replaces the small whole tables (nodes,
  node stats, universes). 18 questions took 50 s. Stars still need `star_layout.py` then `--stars-only --deploy`. The search index builds with the server's own
  memory setting (a 1 GB build gets killed on a PS-40).
- **Host:** PlanetScale Postgres (PS-40, AWS us-east-1, same region as the functions). The site connects as
  its own role through the pooler (port 6432); the sync loads as the default role.
- **Search index:** half-precision embeddings in a narrow table of their own (`qvec`: 777 MB) with a **1-bit
  HNSW index** (294 MB) that finds 400 candidates, then an exact re-rank there; only the top 20 read their
  full question rows. Search's working set is the index plus the vectors (~1.1 GB), so it stays in memory on a
  small node; each search touches ~80 MB of the index, so it needs to be in memory to be fast. Measured on 200 queries against exact full-precision search: #1 matches 97% of the time
  (today's full-precision index: 96.5%), top-20 overlap 91% (96%), 26 ms (53 ms), 292 MB index (1.85 GB;
  a half-precision HNSW was 980 MB).
- **Star snapshot:** `data/stars` and the precomputed Meaning layout go to Vercel Blob in a fresh unguessable
  folder per sync (`STARS_URL`); the server reads them once per instance.
- **Edge cache:** tree, topic, question, snapshot, layout and search responses are cached at Vercel's edge for a
  day; a sync redeploys, which clears it. Most visits never reach a function or the database.
- **No Python in production:** Jev's tree walk runs in TypeScript (`lib/server/walk.ts`, a port of the
  pipeline's beam walk that builds byte-identical requests, so it reuses cached answers). The ask box is
  answer-only there: one Jev request (its own answer and "most people"), nothing written to the corpus.
- **Access:** open, no key; shared by link with TypeSafe rather than posted. `SITE_KEY` is unset in production
  (`proxy.ts` gates the site only when it's set). Endpoints that call Jev have a per-visitor limit.
- **Portrait data:** `scripts/portrait/publish.py` uploads `portrait.json` and the meme images to their own
  unguessable Blob folder (`PORTRAIT_URL`); the portrait, atlas and meme route read it on the server, so neither the
  folder nor the data files are in the repo.
- **Env (Vercel):** `DATABASE_URL` (pooled connection to the copy), `EMBED_STORE=binary`,
  `AI_GATEWAY_API_KEY`, `STARS_URL`, `PORTRAIT_URL` (optional `SITE_KEY` puts the site behind a key). The search model ships inside the function
  (`web/scripts/fetch_model.mjs` runs before `next build`) with only the Linux x64 build of its runtime:
  the runtime is loaded by a dynamic import the tracer can't follow, so `next.config.ts` lists it explicitly,
  and every platform's binaries together would pass Vercel's 250 MB function limit.

## Ask box (private)
Anyone with access can pose a question in one of the three primitives:
| Primitive | User provides | Example |
|---|---|---|
| Noul | a yes/no proposition | "Is a hot dog a sandwich?" |
| Choice | a question + 2..N options (UI cap ~20) | "Best pizza topping?" |
| Score | a question + 2..10 ordered levels, each a concrete situation | "How spicy is too spicy?" |

Flow:
1. **Compose**, with a Jev-powered linter (no generative model in the app): Jev Nouls flag
   arithmetic/date/counting questions, overlapping options, and vague Score levels.
2. **Dedupe** (`02-tree.md` §8): if it's a duplicate, show the canonical card and bump `ask_count`.
3. **Place on the tree**, or send it to an orphan pool and let growth handle it.
4. **Screen + answer in one merged request** (`03-questions.md` §8): content filter, self-assessment,
   both frames, 3 shuffles.
5. **Show the card.** If the answer flips under shuffles, say so loudly.

**Future: compose mode (not built).** A separate mode from search, where the goal is to add a question
rather than find one, and the placement is the show. You pick the primitive, then fill in its spec as
TypeSafe defines it: the question, then options (Choice) or ordered levels (Score) or true/false criteria
(Noul, optional), with the linter above running as you type. On submit the new question appears as a
pending star at the root, and each Jev step plays out on the map as it returns, in Jev's magenta: the dedupe
check (if it's a duplicate, the star merges into the existing one), the placement walk descending level by
level with the losing branches dimming, then the answer (with its shuffle stability) settling the star into
its node. Everything live is Jev; nothing else is called. Until then, search stays find-only.

Asked questions get `origin = asked` and feed the dataset. If the ask box ever goes public, see
`01-jev.md` §8 (the standalone-service clause, liability, abuse controls: rate limits, a bot check, a budget
kill-switch) and ask TypeSafe first.
