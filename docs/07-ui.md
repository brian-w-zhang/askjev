# UI (Next.js, private)

The UI queries Postgres directly (`06-pipeline.md` §5-6) and calls Jev live only from the ask box
and search. The pipeline comes first; the UI is built after the first 10k slice.

## Nebula (main view)
A 3D nebula in which **every node and every displayable question is drawn**, all the time. Detail
reveals itself as the camera gets closer. Precedents: OneZoom (everything drawn, detail on zoom), CAIDA
Walrus (300-500k-node trees drawn as glowing 3D spheres), datamapplot and Nomic Atlas (labels resolve on zoom).

**Layout (deterministic, so you can learn where things are):**
- The root sits at the center. World / Self / Machine are three lobes, 120° apart.
- Every node's children sit on a spherical cap facing away from the node's parent. Siblings are spread
  by repulsion so their subtrees don't overlap, and the cap distance grows with the space the
  children need. This is a 3D balloon tree.
- A node's own questions form a ball of stars around it, with radius ∝ ∛(question count). Every ball has
  the same star density, so big topics look big instead of crowded.
- Inside a ball, a star's direction comes from a 3D PCA of that node's question embeddings, and its
  radius is rank-normalized so the ball fills evenly. Neighboring stars ask similar things.
  `scripts/star_layout.py` (read-only on Postgres) precomputes this into `data/stars/`, which is served by
  `/api/stars`. Re-run it after the pipeline or any restructure. The tree part is computed in the browser.

**Drawing:**
- **Questions:** 100k point sprites in one draw call. The particles themselves are the cloud, like the
  typesafe.ai header.
  - By default each particle takes its hemisphere's color, shaded per L1 branch. Indicator colors come
    from the question's own `question_meta`.
  - Particles that need attention (fragile, large human gap) are bigger and magenta, so they stand out
    from a distance.
- **Nodes:** brighter stars sized by depth.
- **Gas:** a pale halo around every node, colored by hemisphere or by the node's indicator, so where
  Jev is jagged still shows from far away.
- **Filaments:** tree edges drawn as curved light that flows outward, plus the search / Jev-path pulses.
  Question→node edges are never drawn; membership is shown by position.

**Alive, but data-driven:**
- Stars twinkle with an amplitude set by their instability.
- Balls rotate slowly around their node, with deeper levels turning faster. The layout itself never
  moves.
- Idle replay: random stars flare as if their question were being asked again.

**Text on approach:**
- Node labels are prioritized by depth, size, path, and hover. They are placed greedily in screen
  space with collision checks, about 60 at most.
- Close to a topic, its question texts load and the stars nearest the middle of the screen get labels,
  24 at most. Stars that share a text (a template run over many inputs) are labeled by what differs:
  the input or the options.
- Hovering a star shows its text; clicking opens its question card.

**Getting somewhere:**
- One box does both search and ask. As you type, results appear; the last row is "Ask Jev: '...'", which
  opens the ask flow pre-filled.
- **I'm feeling lucky** flies to a uniformly random displayable question.
- A search result, a lucky pick, or a clicked dot is a **journey**: a light runs root → hemisphere → ... →
  topic at a human pace with the camera following, the camera closes in on the question's own dot (a Jev-green
  ring marks it, and the camera keeps it centered as its ball turns), and only then does the card slide in
  from the right.
- The color and filter controls live in a "View.Tool" window that starts collapsed to its title bar. The
  usage hint fades after a few seconds.
- The camera is a damped orbit with a home view.

- **Universe switcher (later):** recolor the same nebula by drift in a chosen universe (terse,
  old-english, negated...). Universes are overlays, so the tree itself never changes.
- **Filter by tag:** kind/shape, primitive, origin. Nodes and stars that don't match dim.

## Look: TypeSafe's brand (typesafe.ai)
askjev is outreach to TypeSafe, so it borrows their visual language: light, printed, dithered, and "old OS".
- **Sky:** a flat, light sky-blue background, with low pink cloud banks near the horizon like the
  typesafe.ai hero. The questions are colored particles (World teal, Self pink, Machine blue). Filaments
  use the hemisphere's color, so they read against the sky. Grey never appears in the 3D view (it
  muddies the particles). The whole 3D view passes through an ordered-dither (Bayer) filter onto the
  brand palette at 2 px cells. Text labels sit above the filter in HTML, so they stay sharp.
- **Palette:** ink `#1E1E1E`, off-white `#FEFEFE`, window grey `#DEDEDE`, pink `#F386A1`, magenta `#D45BB6`,
  teal `#09AEA1`, Jev green `#03AA5C`, sage `#ABBAB9`, plus sky and chart blue. Indicators run from blue (steady)
  to magenta (worth a look). Jev's own walk is Jev green.
- **Type:** TypeSafe uses Die Grotesk C, LisaTerminal Paper, and JetBrains Mono. The first two are licensed,
  so askjev uses free stand-ins: Inter Tight (headings/body), VT323 (window chrome, chips, labels), and
  JetBrains Mono light (tiny captions).
- **Components:** every panel is a flat OS window. Each has a black title bar in pixel type ("Color Tool 1.1"),
  a grey body, a hard double border, no rounding, and no blur. Tags are black or colored chips in pixel type.
  Meters use ■ markers. The page also has crop-mark corners, dotted leader lines, and a vertical base64
  caption.

## Side panel: question cards
- Question text, primitive, frame toggle (self / human / human@country).
- Distribution bars (Choice/Noul) or bands (Score; never the interpolated scalar).
- Stability strip (agreement across shuffles; a "fragile" badge) and, where sampled, the answer in each
  universe side by side.
- Jev's self-assessment (objective / ambiguous / disagreement) next to the measured values.
- `ask_count` and the follow-up thread (`question_links`).
- Human overlay and/or truth marker where available.
- A link to the raw request/response and the served version.
- Framing text on Self cards: "Jev's default", never "Jev believes".

## Findings page
The 3-5 findings in the standard format (`05-experiments.md`), with charts and links into
the map. This is the page sent to TypeSafe.

## Search (instant, then refined)
- As you type: a local embedding + pgvector/trigram search return results in **~50 ms** (`06-pipeline.md` §6).
- **The animation is decoupled from latency.** The top result's path is known instantly, and the camera
  and a light pulse travel root → hemisphere → L1 → ... at a **human pace** (~300-500 ms per level,
  eased) so the eye can follow. Branches brighten in proportion to relevance.
- **Jev refines in the background.** One request (~150 ms) reranks the top 20, and results reorder smoothly. With
  "show Jev's path" on, Jev's own beam walk animates as a second light, and it forks visibly where Jev
  and the embeddings disagree.

## Ask box (private)
Anyone with access can pose a question in one of the three primitives:
| Primitive | User provides | Example |
|---|---|---|
| Noul | a yes/no proposition | "Is a hot dog a sandwich?" |
| Choice | a question + 2..N options (UI cap ~20) | "Best pizza topping?" |
| Score | a question + 2..10 ordered levels, each a concrete situation | "How spicy is too spicy?" |

Flow:
1. **Compose**, with a Jev-powered linter (no generative model in the app): Jev Nouls flag
   arithmetic/date/counting questions, overlapping options, and vague Score levels.
2. **Dedupe** (`02-tree.md` §8): if it's a duplicate, show the canonical card and bump `ask_count`.
3. **Place on the tree**, or send it to an orphan pool and let growth handle it.
4. **Screen + answer in one merged request** (`03-questions.md` §8): content filter, self-assessment,
   both frames, 3 shuffles.
5. **Show the card.** If the answer flips under shuffles, say so loudly.

Asked questions get `origin = asked` and feed the dataset. If the ask box ever goes public, see
`01-jev.md` §8 (the standalone-service clause, liability, abuse controls: rate limits, a bot check, a budget
kill-switch) and ask TypeSafe first.
